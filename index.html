❓ What are the benefits of using Worktree instead of cloning the repository again?

                    

                        

                            

                                Feature
                                Traditional Clone
                                Git Worktree
                            

                            

                                Disk space
                                Copies the entire repo + `.git`
                                Shares database (minimal space)
                            

                            

                                Dependencies
                                Must download/sync npm, sbt, maven etc. again (takes minutes).
                                Skip the wait! Can usually start code immediately.
                            

                            

                                Git Sync
                                Each clone must be fetched separately.
                                Shared database = instant updates.
                            

                        

                        💡 Note on ports: If running multiple instances and experiencing port conflicts (e.g. port 8080), this is easily handled via application profiles (e.g. an %agent profile or environment variables).
                    

                


                

                    
❓ Why do we use git fetch instead of git pull?

                    
git fetch only downloads info about new branches and updates from remote (Bitbucket) into your local database without altering your files. git pull also attempts to merge updates directly into your active branch, which can cause unexpected merge conflicts while you work.

                


                

                    
❓ How do I update the worktree folder if the agent needs my latest code (or vice versa)?

                    

                        Since all worktrees share the same underlying Git database, you can synchronize in two ways:

                        • Via remote (recommended): Commit and push changes from your folder, then run git pull or git merge origin/main in the other folder.

                        • Locally without pushing: Stand in e.g. the agent folder and merge your local branch directly:

                        
git merge main

                    

                


                

                    
❓ Can I have multiple IntelliJ windows open simultaneously?

                    
Yes! That is the whole point. You open your main folder in one IntelliJ window and the worktree folder (e.g. agent folder) in another window. They operate completely independently.
